# ADR 0004 — Verified live share archive (2026-10-16)

The user explicitly authorized transferring the 338 reports approved by the preceding dry-run, excluding the conflicting snapshot. This supersedes the simulation-only restriction for that operation. Apply accepts an approved simulation as an allowlist, rechecks every file against its approved SHA-256 and the current tenant-scoped database evidence, never imports new files, and never expands the allowlist to newly arrived reports.

Copy through a unique temporary file inside `archiviati`, flush, hash, publish without overwrite and hash the final destination. Preserve original creation/modification timestamps. Retain the original on any failure. Hold a Windows source handle with read/delete access and no write/delete sharing until explicit deletion by handle, so a path replacement between hash and delete cannot remove a different report. Keep the destination read-locked during source deletion. Native handle deletion is intentionally Windows-only; there is no unsafe cross-platform path-delete fallback.

A create-new, delete-on-close archive-directory lock serializes cooperating DMT writers. An append-only local JSONL journal records exact temporary paths, verification and results, flushing before deletion. Crashes leave either the original or a verified destination (and database evidence); a re-run verifies existing destinations and can complete without overwriting. Files absent at source count as already archived only if destination and database evidence still match. No archive directory is removed during cleanup.

Monthly compression must run at the first useful opportunity after its due time, including missed runs. Current-month loose files are excluded. No dependency on this VM being awake at 23:59 and no Windows Task Scheduler job will be created. The month timestamp basis and background activation are documented with the implementation; copy timestamps are preserved so source creation dates are not replaced by the transfer date.

The timestamp basis remains the JSON collection date (`collected_at`, Europe/Rome), independent of file-copy timestamps. This also supports historical inventory questions. Creation/modification timestamps are preserved on transferred files and recorded in the local journal and ZIP manifest; the current SQLite schema stores collection/import dates but does not yet index filesystem timestamps. Software installation dates remain in raw evidence, not the indexed software table. Do not present filesystem creation or installation dates as the observation time.

The opt-in catch-up host service checks on startup and every 15 minutes, using relational metadata to skip all current-month payloads. It processes closed months only (no earlier than local midnight after month end), catches up multiple missed months and does not reimport archived data. Existing DMT ZIPs are verified against their manifest and acquired evidence before adding late arrivals. Updates use a verified temporary ZIP and atomic replacement with a retained previous ZIP. Corrupt/unrecognized ZIPs, ambiguous filenames and unacquired evidence fail closed.

Compression verifies entry names, lengths, hashes, tenant, snapshot IDs, collection month and the published ZIP before deleting loose files by locked handle. Retained previous ZIPs have explicit recorded paths and no automatic retention deletion yet. A partial loose-file cleanup can be retried against the existing verified ZIP without rewriting it. On SMB, atomic replacement support is required for updates; failure preserves loose files and archives for review.
